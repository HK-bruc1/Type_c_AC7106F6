# AC7106F 六线 Type-C 耳机添加 MIC 按键说明

## 1. 文档目的

本文说明 JL7106F/AC7106F 六线 Type-C 耳机中 MIC 线控按键的硬件接法、ADC 检测原理、SDK 配置方法，以及本项目中“MIC 已经正常，但配置 PA4 后仍检测不到按键”的问题原因与解决方案。

本次问题的最终结论是：

- `MIC_BIAS` 节点直接接到主控 `PA4/ADC5`，PA4 是 MIC 按键电压的实际采样脚。
- R3 1.5 kΩ 并不是与 PA4 并联。R3 连接在 `PA0/MICLDO` 与 `MIC_BIAS/PA4` 采样节点之间，是 AD 按键分压网络的上拉电阻；PA0 负责提供 MICLDO 偏置电源。
- MIC 音频采集和 MIC 按键检测是两条不同的采样路径；MIC 有声音不代表按键路径已经正确。
- 这套接法在本项目中必须配合六线模式使用。只配置 `PA4` 和使能 `MICKEY` 还不够，必须在“功能配置”中将耳机类型选择为“六线耳机”。
- 本项目之前仍配置为四线耳机，MICKEY 驱动错误地使用 `DACLN` 作为 MIC 公共端参考，导致 PA4 按键电压计算错误，最终检测不到按键。

## 2. 六线耳机硬件连接原理

### 2.1 六线接口的组成

六线耳机将左右声道和 MIC 分别使用独立的正、负端：

| 信号 | 连接 | 作用 |
| --- | --- | --- |
| 左声道正端 | `DACLP` | 左声道音频输出 |
| 左声道负端 | `DACLN` | 左声道差分负端 |
| 右声道正端 | `DACRP` | 右声道音频输出 |
| 右声道负端 | `DACRN` | 右声道差分负端 |
| MIC 正端/按键端 | `M/K`、`MIC_BIAS` | MIC 偏置、MIC 音频信号和按键检测共用节点 |
| MIC 负端 | `M-`、`AVSS` | MIC 独立模拟地 |

六线模式与四线模式的关键区别是：六线耳机的 MIC 负端直接连接 `AVSS`，不与 `DACLN` 共用。

### 2.2 本项目的 MIC 和按键接法

根据 `JL7106F_TYPE-C耳机原理图V1.1.pdf`，首先需要明确 PA0、PA4 和 MIC_BIAS 的连接关系：

```text
PA0 / MICLDO（3.0 V）
          |
       R3 1.5 kΩ             外置偏置/上拉支路
          |
          +--------- MIC_BIAS / M/K / MIC正端
                          |
                          +--------- PA4 / ADC5
                          |          MIC按键直流电压采样脚
                          |
                          +--------- 按键 -------- M- / AVSS
                          |
                          +--------- C5 ----------- MICIN
```

从 `MIC_BIAS` 节点看，它同时存在以下分支：

1. 直接连接 `PA4/ADC5`，由 PA4 的高阻 ADC 输入检测按键电压。
2. 通过外置 R3 1.5 kΩ 连接 `PA0/MICLDO`，由 PA0 提供 3.0 V MIC 偏置电源。
3. 连接耳机的 `M/K` 和 MIC 正端。
4. 通过 C5 耦合到 `MICIN`，用于采集 MIC 交流声音。
5. 按键按下时，通过按键连接到 `M-/AVSS`。

因此，准确的描述不是“R3 与 PA4 并联”，也不是“PA0 检测 MIC 按键”。标准 AD 按键等效电路为：

```text
PA0/MICLDO（3.0 V）
          |
       RUP = R3 1.5 kΩ             分压上臂/上拉电阻
          |
          o---------------- PA4/ADC5
          |                 高阻ADC，只采样此节点电压
          |
       RKEY                       分压下臂/按键电阻
     0 Ω / 200 Ω / 400 Ω
          |
        AVSS
```

- PA0 是偏置电源输出端。
- R3 是从 PA0/MICLDO 到 `MIC_BIAS` 采样节点的分压上臂。
- 按键电阻是从 `MIC_BIAS` 采样节点到 AVSS 的分压下臂。
- PA4 直接接在上下两臂的中点，只负责采样，不属于上臂或下臂，也不能称为与 R3 并联。
- `MIC_BIAS`、M/K 和 PA4 实际上是同一个采样节点。

原理图只画了一个直接短接的 PP 按键，所以这个按键的 `RKEY=0 Ω`；按键闭合时采样中点被拉到 AVSS。软件中的 200 Ω 和 400 Ω 分别用于可选的 UP、DOWN 电阻按键。

“R3 与 PA0 串联”也不是最准确的元件关系表述，因为 PA0 是 MICLDO 电压源端，不是一个串联元件。准确说法是“R3 一端接 PA0/MICLDO，另一端接 MIC_BIAS/PA4 采样节点”。只有从按键按下后的电流路径看，才表现为 `PA0/MICLDO -> R3 -> RKEY -> AVSS`，此时 R3 与按键电阻位于同一电流通路中。

上述等效图重点表示 AD 按键分压。实际电路中的驻极体 MIC 也连接在 MIC_BIAS 与 AVSS 之间，未按键时会形成额外直流负载，所以 PA4 空闲电压还会受到 MIC 静态电流影响。

包含 MIC 音频输入后的完整连接可以简化为：

```text
MICLDO（PA0，3.0 V）
        |
      R3 1.5 kΩ
        |
        +---------------- MIC_BIAS / M/K / MIC正端
        |                         |
        |                         +---- 按键 ---- AVSS / M-
        |
        +---------------- PA4 / ADC5（按键直流电压检测）
        |
       C5 1 µF
        |
      MICIN
        +---------------- PA3 / ADC0（当前工具选择的MIC输入）
        |
        +---------------- PA2（与MICIN并联，用于兼容芯片版本）

MIC负端 -------------------------------- AVSS / M-
```

原理图中 C5 后面的 `MICIN` 网络同时连接 PA2 和 PA3。两个引脚之间没有串联器件，属于同一网络的并联连接，不是 MIC 信号依次经过 PA2、PA3 的串联连接。

当前可视化工具生成：

```c
#define TCFG_ADC0_AIN_SEL  2
```

工具中数值 2 对应的选项名称是“PA3（A/B/C版芯片用PA2）”。因此，本项目当前软件选择和已验证有效的物理 MIC 输入应记录为 `PA3/ADC0`；PA2 虽然也连接在同一个 MICIN 网络上，但不是当前配置所选择的输入名称。这种并联接法用于兼容不同芯片版本的 MIC 输入引脚映射。

仓库中的 `3-1.USB_MIC上行链路测试点说明.md` 记录的是早期 PA2 接线和诊断结果；`3-2.RDX在线录音业务移植评估与实施路线.md` 已明确说明当前工程统一选择 PA3。后续描述和测试应以 PA3 为当前基线。

`MIC_BIAS` 节点同时承载两类信息：

1. MIC 产生的交流音频信号。
2. 按键按下后产生的直流电压变化。

两类信号通过不同方式送入芯片，因此可以互不影响地完成录音和按键检测。

### 2.3 R3 1.5 kΩ 的作用

R3 从 `MICLDO` 接到 `MIC_BIAS`，主要有三个作用：

1. 为驻极体 MIC 提供工作电流和直流偏置。
2. 与按键电阻构成分压网络，使不同按键产生不同的 ADC 电压。
3. 按键将 `MIC_BIAS` 短接到 `AVSS` 时限制电流，避免直接短路 MICLDO。

当前 MICLDO 配置为 3.0 V，按下 0 Ω 的播放/暂停按键时，忽略器件压降后的最大电流约为：

```text
I = 3.0 V / 1.5 kΩ = 2 mA
```

因此，这种接法既可以把按键节点拉到接近 0 V，又能通过 R3 将短路电流限制在合理范围内。

电流路径也可以直观地表示为：

```text
未按键：PA0/MICLDO -> R3 -> MIC -> AVSS

按下键：PA0/MICLDO -> R3 -> 按键 -> AVSS
                         |
                         +-> PA4检测到接近0 V
```

PA4 配置为高阻 GPADC 输入，正常情况下不会明显分流 MIC_BIAS 电流，只负责观察该节点的电压变化。

### 2.4 未按键和按下按键时的电压

未按键时，MIC 本身会从 `MIC_BIAS` 取电，R3 上产生压降。`MIC_BIAS/PA4` 不会等于完整的 3.0 V，常见直流电压约为 1～2.5 V，具体值与 MIC 型号和静态电流有关。

按下原理图中的播放/暂停按键后，`M/K` 被短接到 `M-/AVSS`：

```text
未按键：PA4 = MIC正常偏置电压，通常明显高于 0 V
按下键：PA4 ≈ 0 V
```

PA4 的 GPADC 根据这个直流电压变化识别按键。

### 2.5 为什么 MIC 正常不代表按键也正常

MIC 音频和按键电压虽然来自同一个 `MIC_BIAS` 节点，但进入芯片的路径不同：

```text
MIC交流声音 -> C5隔直耦合 -> MICIN -> PA3/ADC0 -> 音频ADC -> USB MIC

按键直流电平 ------------> PA4/ADC5  -> GPADC   -> MICKEY驱动
```

C5 只允许交流音频变化进入 MICIN，并隔离 MIC 节点的直流偏置。当前配置由 PA3/ADC0 采集该交流信号；PA4 则直接读取 `MIC_BIAS` 的直流电压。

因此可能出现以下情况：

- PA3/ADC0 音频路径配置正确，所以 USB MIC 已经有声音。
- PA4 或 MICKEY 的参考方式配置错误，所以按键仍然检测不到。

这正是本项目本次遇到的情况。

## 3. SDK MICKEY 驱动原理

### 3.1 应使用 MICKEY，而不是普通 ADKEY

普通 ADKEY 通常使用独立的 ADC 电阻按键网络。耳机线控按键与 MIC 共用偏置节点，SDK 为这种场景提供了专用的 `MICKEY` 驱动。

本项目应保持：

```c
#define TCFG_ADKEY_ENABLE   0
#define TCFG_MICKEY_ENABLE  1
```

对应的主要文件为：

- `SDK/apps/earphone/board/mickey_config.c`
- `SDK/apps/common/device/key/mickey.c`
- `SDK/apps/earphone/board/br56/sdk_config.c`
- `SDK/apps/earphone/mode/pc/pc_key_msg_table.c`

### 3.2 外置 MICLDO 偏置模式

音频 ADC0 的供电端口选择 `MIC_LDO (PA0)` 后，生成配置为：

```c
#define TCFG_ADC0_BIAS_SEL  33
```

`33` 中包含 `AUDIO_MIC_LDO_PWR` 标志。`mickey_config.c` 检测到该标志后，进入外置偏置电阻分支：

```c
gpio_set_mode(IO_PORT_SPILT(mickey_res_table.mickey_pin),
              PORT_INPUT_FLOATING);
gpio_set_function(IO_PORT_SPILT(mickey_res_table.mickey_pin),
                  PORT_FUNC_GPADC);

g_mickey_platform_data.micbias_ad_channel =
    adc_io2ch(mickey_res_table.mickey_pin);
g_mickey_platform_data.pull_up_value =
    mickey_res_table.extern_bias_res;
```

当前 `mickey_pin` 为 `IO_PORTA_04`，`adc_io2ch()` 会将 PA4 转换为它对应的 ADC5 通道。外置上拉电阻则取配置中的 1500 Ω。

当使用这个外置 MICLDO 方案时，按键算法使用的是 `extern_bias_res`。音频配置中的“MIC BIAS 上拉电阻档位”不是本电路的实际 R3 阻值，不能用它代替按键配置中的 1500 Ω。

### 3.3 按键分压计算

AD 按键确实需要通过电阻分压识别。本项目中，R3 1.5 kΩ 是固定的上拉电阻，0 Ω、200 Ω、400 Ω 是不同按键闭合时接入到 AVSS 的下拉电阻，PA4 采样两者之间的分压中点。

设：

- `VREF` 为 MICLDO 相对 MIC 公共端的电压。
- `RUP` 为外置偏置电阻，本项目为 1500 Ω。
- `RKEY` 为按下某个按键时接入的电阻。
- `VKEY` 为按键按下后的理论采样电压。

理论分压为：

```text
VKEY = VREF × RKEY / (RUP + RKEY)
```

本项目当前配置为：

| 按键 | 按键电阻 | 3.0 V MICLDO 下的理论电压 |
| --- | ---: | ---: |
| PP，播放/暂停 | 0 Ω | 0 V |
| UP，音量加 | 200 Ω | 约 0.353 V |
| DOWN，音量减 | 400 Ω | 约 0.632 V |

原理图目前只画出了一个直接短接的按键，因此实际使用的是 `PP=0 Ω`。200 Ω 和 400 Ω 配置用于支持带音量加减电阻的三键线控；如果硬件没有这两个按键，它们不会被触发。

SDK 不是只用固定 ADC 数值判断，而是同时采样 MICLDO 作为参考，再根据电阻比例计算理论电平。这样可以降低 MICLDO 电压误差对按键判断的影响。

### 3.4 无按键快速判断阈值

当前驱动使用最大按键电阻 400 Ω 计算无按键阈值：

```text
V_DOWN  = 3.0 × 400 / (1500 + 400) ≈ 0.632 V
V_NOKEY = V_DOWN × 1.5                 ≈ 0.947 V
```

当 PA4 相对正确参考端的电压明显高于约 0.95 V 时，驱动直接判定为无按键。正常 MIC 的空闲偏置通常高于这个值；按下 0 Ω 按键后电压接近 0 V，驱动选择 PP 按键。

如果实际 MIC 空闲偏置低于约 0.95 V，可能出现误判。这时应检查 MIC 静态电流、MIC 极性、R3 实际阻值和焊接情况，而不是只修改软件阈值。

## 4. 四线和六线模式为什么影响 MIC 按键

### 4.1 四线耳机的参考方式

四线耳机通常只有以下四个端子：

```text
L、R、公共地G、MIC/KEY
```

MIC 负端与扬声器公共端共用。在本 SDK 的四线实现中，MICKEY 使用 `DACLN` 的 ADC 电压作为公共端参考：

```c
#if (TCFG_EARPHONE_TYPE == 0) // 四线模式
    g_mickey_platform_data.dacln_ad_channel = AD_CH_AUDIO_DACLN;
#else
    g_mickey_platform_data.dacln_ad_channel = -1;
#endif
```

驱动随后计算：

```text
按键有效电压 = PA4采样电压 - DACLN采样电压
MICLDO参考电压 = MICLDO采样电压 - DACLN采样电压
```

这对 MIC 负端确实与 DACLN 共用的四线硬件是合理的。

### 4.2 六线耳机的参考方式

本项目的六线硬件中：

```text
DACLN -> 左声道差分负端
DACRN -> 右声道差分负端
M-    -> AVSS，MIC独立负端
```

因此，`DACLN` 不再是 MIC 公共端，不能从 PA4 电压中减去 DACLN 电压。选择六线模式后：

```c
g_mickey_platform_data.dacln_ad_channel = -1;
```

`mickey.c` 会将 MIC 公共端参考值设为 0，即按 PA4 相对 AVSS 的电压进行判断，这才与原理图一致。

这里的“六线模式”不是只影响声道数量的显示选项，而是决定 MICKEY 如何解释 PA4 电压的硬件拓扑开关：

```text
PA4配置：告诉驱动“去哪个IO读取MIC_BIAS电压”

六线配置：告诉驱动“PA4电压应以AVSS为参考，不能减去DACLN”
```

所以，在本项目的六线硬件上，仅把 MIC 按键 IO 配置成 PA4 并不能保证按键工作。只有同时配置 `TCFG_EARPHONE_TYPE=2`，PA4/ADC5 的采样值才会按照实际的 `MIC_BIAS -> 按键 -> AVSS` 电路进行判断。若仍选择四线模式，驱动会错误减去 DACLN 电压，这套 PA4 按键接法就无法正确发挥作用。

## 5. 本次遇到的问题

### 5.1 现象

调试过程中的现象为：

1. USB MIC 已经测试有声音，说明 MIC、MICIN、当前选择的 PA3/ADC0 和 USB MIC 上行链路基本正常。
2. 在按键配置中使能了 MIC 按键。
3. 将 MIC 按键 IO 从原来的 PB4 改为原理图对应的 `PA4/ADC5`。
4. 外置偏置电阻也配置为 1500 Ω。
5. 烧录后按下 MIC 按键，软件仍然检测不到。

### 5.2 当时遗漏的配置

虽然 PA4 和 MICKEY 已经配置，但“功能配置”中的耳机类型仍然是：

```c
#define TCFG_EARPHONE_TYPE  0 // 四线耳机
```

实际硬件却是六线耳机。

### 5.3 检测不到的根本原因

四线配置使 `mickey_config.c` 添加了 `AD_CH_AUDIO_DACLN` 参考通道。驱动把 PA4 电压减去 DACLN 电压后再判断按键。

但六线硬件的按键是把 `MIC_BIAS/PA4` 短接到 `AVSS`，不是短接到 DACLN。DACLN 是差分 DAC 的负端，可能具有非零共模电压，也可能随音频输出变化。

按键按下时可能出现：

```text
PA4采样值接近 0
DACLN采样值大于 0
PA4 - DACLN 得到负值
```

驱动中的相关变量是无符号 16 bit 类型。负值可能发生无符号回绕，变成一个很大的数，随后被无按键条件直接过滤；即使没有发生明显回绕，使用错误参考也会使按键理论电平和实测电平无法匹配。

所以问题不是“PA4 不支持 ADC5”，也不是“MIC 已经有声音就不需要其他配置”，而是软件仍按四线电气拓扑解释六线硬件的 PA4 电压。

## 6. 解决方案

### 6.1 在功能配置中选择六线耳机

在杰理工程工具中选择：

```text
功能配置
  -> 耳机类型选择
  -> 六线耳机
```

工具生成后应确认：

```c
#define TCFG_EARPHONE_TYPE  2
```

根目录 `src/*.json` 是工具管理的产品资源，应通过杰理工程工具修改，不建议手工编辑 JSON。

### 6.2 使用六线对应的差分 DAC 输出

六线耳机的左右声道分别使用差分正、负端，应配置为：

```c
#define TCFG_AUDIO_DAC_CONNECT_MODE  DAC_OUTPUT_LR
#define TCFG_AUDIO_DAC_MODE          DAC_MODE_DIFF
```

本次在工具中选择六线耳机后，输出方式已从 `DAC_MODE_VCMO` 同步调整为 `DAC_MODE_DIFF`。

### 6.3 音频 ADC 和 MICLDO 配置

本项目当前正确配置为：

```c
#define TCFG_AUDIO_MIC_LDO_VSEL  7  // 3.0 V
#define TCFG_ADC0_ENABLE         1
#define TCFG_ADC0_AIN_SEL        2  // PA3（A/B/C版芯片对应PA2）
#define TCFG_ADC0_BIAS_SEL       33 // MIC_LDO (PA0)
```

这与原理图的 `MICLDO -> R3 1.5 kΩ -> MIC_BIAS` 偏置接法，以及 `MIC_BIAS -> C5 -> MICIN -> PA3/PA2并联节点` 音频接法一致。当前软件实际选择 PA3 作为 ADC0 输入。

### 6.4 MIC 按键配置

按键配置应生成：

```c
#define TCFG_ADKEY_ENABLE   0
#define TCFG_MICKEY_ENABLE  1

const struct mickey_res_value mickey_res_table = {
    .mickey_pin      = IO_PORTA_04,
    .extern_bias_res = 1500,
    .pp_res_value    = 0,
    .up_res_value    = 200,
    .down_res_value  = 400,
};
```

其中：

- `IO_PORTA_04` 对应芯片 `PA4/ADC5`。
- `extern_bias_res=1500` 对应原理图 R3。
- `pp_res_value=0` 对应原理图中按键直接短接 M/K 和 M-。
- `up_res_value=200`、`down_res_value=400` 仅在三键硬件中使用。

### 6.5 修正后的判断路径

修正前：

```text
硬件是六线
    + 软件配置为四线
    + PA4电压错误减去DACLN电压
    = MIC按键检测不到或判断不稳定
```

修正后：

```text
硬件是六线
    + TCFG_EARPHONE_TYPE=2
    + MIC公共端按AVSS处理
    + PA4直接检测MIC_BIAS相对AVSS的电压
    = 按键电平模型与实际硬件一致
```

换句话说，完整解决方案必须同时具备两个条件：

1. `mickey_pin=IO_PORTA_04`：指定 PA4 是 MIC_BIAS 的按键采样脚。
2. `TCFG_EARPHONE_TYPE=2`：指定 PA4 采样值按六线硬件、以 AVSS 为参考进行解释。

缺少其中任意一个条件，都不能得到正确的 MIC 按键检测结果。

## 7. 编译与验证

### 7.1 重新生成并编译

由于本次从关闭 MICKEY 改为使能 MICKEY，涉及按键驱动源文件的条件选择，建议先清理再全量编译。

在 `SDK/` 目录执行：

```bat
.vscode\winmk.bat clean
.vscode\winmk.bat all
```

编译完成后确认仓库根目录 `output/` 中生成了新的：

- `jl_isd.bin`
- `jl_isd.fw`
- `update.ufw`

编译通过只能证明配置和代码能够正确构建，不能代替硬件按键验证。

### 7.2 静态配置检查

烧录前至少确认以下值：

```text
TCFG_EARPHONE_TYPE          = 2
TCFG_MICKEY_ENABLE          = 1
TCFG_ADKEY_ENABLE           = 0
TCFG_AUDIO_DAC_MODE         = DAC_MODE_DIFF
TCFG_AUDIO_DAC_CONNECT_MODE = DAC_OUTPUT_LR
TCFG_AUDIO_MIC_LDO_VSEL     = 7
TCFG_ADC0_ENABLE            = 1
TCFG_ADC0_AIN_SEL           = 2（工具显示PA3）
TCFG_ADC0_BIAS_SEL          = 33
mickey_pin                  = IO_PORTA_04
extern_bias_res             = 1500
pp_res_value                = 0
```

### 7.3 硬件电压检查

上电后用万用表测量：

| 测试点 | 空闲状态 | 按下 PP 键 | 异常时检查方向 |
| --- | --- | --- | --- |
| MICLDO/PA0 | 约 3.0 V | 约 3.0 V | MICLDO 配置和 PA0 焊接 |
| MIC_BIAS/PA4 | 常见约 1～2.5 V | 接近 0 V | R3、MIC 极性、按键、PA4 焊接 |
| M-/AVSS | 0 V | 0 V | 六线 MIC 负端是否真正接 AVSS |

如果 PA4 按下后没有接近 0 V，应优先检查硬件连接，不要先修改软件阈值。

### 7.4 软件功能检查

烧录后连接电脑，依次检查：

1. 单击 PP 键是否产生播放/暂停 HID 按下和抬起事件。
2. 双击是否执行下一曲。
3. 三击是否执行上一曲。
4. 如果硬件实现了 200 Ω 和 400 Ω 按键，再检查音量加、音量减。

当前 PC 模式的映射位于：

```text
SDK/apps/earphone/mode/pc/pc_key_msg_table.c
```

不同主机对多击事件的处理策略不同。Windows 支持当前 PP 多击映射；Android/iOS 分支会屏蔽多击组合，但仍应能够识别基本的按下和抬起。

### 7.5 必要时增加限频 ADC 日志

如果电压测量正常但仍无按键事件，可以在 `mic_get_key_value()` 中临时、限频打印以下值：

```text
adc_micldo
adc_mic
adc_vcmo
diff_val
diff_pp
diff_up
diff_down
最终key值
```

六线模式下应看到 `adc_vcmo=0`；按下 PP 键时 `adc_mic` 和 `diff_val` 应明显降到接近 0。

不要每 10 ms 都打印一次，否则串口打印会影响实时任务。诊断完成后应删除或关闭临时日志。

## 8. 常见问题排查

| 现象 | 可能原因 | 检查方法 |
| --- | --- | --- |
| MIC 有声音，但按键完全无反应 | 耳机类型仍为四线 | 确认 `TCFG_EARPHONE_TYPE=2` |
| 文档或日志把当前 MIC 写成 PA2 | 沿用了早期接线记录 | 当前配置确认 `TCFG_ADC0_AIN_SEL=2`，工具显示 PA3 |
| 配置 PA4 后仍读取错误 | 音频供电不是 MIC_LDO 外置电阻模式 | 确认 `TCFG_ADC0_BIAS_SEL=33` |
| PA4 按下后电压不变 | 按键、M/K、M- 或 PA4 硬件未接通 | 直接测量 PA4 和 AVSS |
| 空闲时持续误报按键 | MIC_BIAS 空闲电压过低或电阻配置错误 | 测量空闲电压，核对 R3=1.5 kΩ |
| 只有播放/暂停键有效 | 硬件只实现了 0 Ω 按键 | 确认是否实际装有 200 Ω、400 Ω 按键 |
| 驱动代码未进入固件 | 使能宏改变后未清理旧构建文件 | 执行 `clean` 后重新 `all` |
| ADC 已识别按键但电脑无动作 | PC 按键消息或 USB HID 映射问题 | 检查 `pc_key_msg_table.c` 和 PC 消息处理 |
| 播放音乐时按键误判 | 仍错误使用 DACLN 作为参考 | 确认六线模式下 `dacln_ad_channel=-1` |
| PA4 被其他功能重新配置 | IO 复用冲突 | 检查 RDEC、LED7、DLOG 等功能是否启用 |

当前工程中引用 PA4 的 RDEC 和离线 DLOG 功能均为关闭状态，没有发现已启用的 PA4 复用冲突。但以后启用新功能时仍需要重新检查 IO 占用。

## 10. 总结

本项目的 MIC 按键硬件接法没有问题：`MIC_BIAS` 直接接到 PA4/ADC5，PA4 是 MIC 按键的实际 ADC 采样脚；同一个 MIC_BIAS 节点通过外置 R3 1.5 kΩ 接到 PA0/MICLDO，由 PA0 提供 3.0 V 偏置。MIC 音频经过耦合电容进入同时连接 PA2、PA3 的 MICIN 网络，当前可视化工具选择 PA3/ADC0 进行音频采集。按键按下时将 MIC_BIAS 短接到 AVSS，使 PA4 检测到接近 0 V。

本次检测不到按键的关键原因，是只完成了 PA4 和 MICKEY 配置，却遗漏了“耳机类型选择”。四线模式会把 DACLN 当成 MIC 公共端参考，而实际六线硬件的 MIC 公共端是 AVSS，导致按键电压计算错误。

这套 PA4 MIC 按键方案必须工作在六线配置下。将功能配置改为六线耳机，使 `TCFG_EARPHONE_TYPE=2`，驱动才会以 AVSS 而不是 DACLN 作为 PA4 按键电压参考。再配合 `DAC_MODE_DIFF`、`PA4/ADC5`、PA0/MICLDO 3.0 V 和外置 1.5 kΩ 后，软件的电压模型才与实际六线电路完全一致。
