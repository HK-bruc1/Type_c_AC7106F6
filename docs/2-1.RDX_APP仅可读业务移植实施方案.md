> 目标工程：AC710N / BR56 Type-C 有线耳机
> 实施基线：`a03e293`
> 前置文档：`docs/0.RDX_BLE_MVP0实施方案.md`

## 1. 当前结论

MVP0 已完成 RDX 广播、GATT、Identity、Notify、AppKey 认证和最小 APP 握手，下一阶段应进入 APP 可见的设备业务移植。实施必须继续遵守“模块化、最小侵入 JL 原生平台”的原则，并按副作用从低到高分成三个独立批次：

1. 只读业务：具名能力位、真实能力值、查询设备授权与 SN、查询待机时间；
2. 绑定业务：RDX 独立状态存储、运行时 Bound 广播位、APP 绑定；
3. 状态清理业务：APP 解绑、恢复出厂、ACK 后仅断开 RDX BLE。

录音、文件、存储格式化、Wi-Fi、SPI、OTA、LED、马达、充电仓与耳机配对等外设业务不在本阶段范围内。特别是 `*APP#devpair#` / `*APP#devunpair#` 属于充电仓与耳机的外设配对，不得与 APP 绑定状态混为一谈。

本方案同时记录实施边界和验收合同。第一批只读业务已完成代码实施，但仍有目标 APP Golden Trace、广播实测和 USB 共存回归待补齐。第二批已完成代码实施，范围严格限定为 RDX 自有状态、运行时 Bound 和绑定命令；绑定、重复绑定、正常断连、冷启动持久化和 USB 共存已有实机日志证据，VM 写失败事务仍待补测，未完成前不作第二批完整签收。第三批解绑、恢复出厂、ACK 后延迟断开 RDX BLE 和 pending action 已完成代码实施、干净构建与 RDX OFF 完整 ELF 验证；独立 `unbound`、恢复出厂、Bound 广播恢复和解绑后冷启动持久化已通过实机日志验证，但 `bound=0` 直接分支、重复解绑、pending 并发、提前断连取消、VM 写失败和完整压力回归仍未验证，不作第三批完整签收。

## 2. 实施目标与硬约束

### 2.1 目标

- 让目标 APP 在 MVP0 握手后读取真实、边界明确的设备管理信息；
- 以小步提交方式加入绑定、解绑和恢复出厂；
- 为量产身份和后续业务保留可替换的 Provider/Adapter 接口；
- 保持 USB Speaker、Mic、HID、CVP 和 RDX BLE 共存基线；
- 保持 RDX OFF 零源码、零符号、零 VM、零运行行为；
- 保持官方 `librdxApp.a` 只抽取 `rdx_encryption.c.o`。

### 2.2 不允许发生的事情

- 不整体移植 701 的 `rdx_app.c`、`rdx_vm.c` 或 `rdx_protocol.c.o`；
- 不引入 701 的录音、文件、Wi-Fi、TWS、经典蓝牙、OLED、存储格式化或电源副作用；
- 不在 USB、UAC、音频、PC 模式或 JL 核心模块中加入 RDX 业务判断；
- 不为每个业务批次增加平行的产品总开关；
- 量产配置不得用虚假能力位宣告未实现业务；当前开发阶段允许显式使用命令发现 Ability 组合打开 APP 页面，但必须与真实产品能力区分并在量产前重新收敛；
- 不通过整机 `cpu_reset()` 完成解绑或恢复出厂；
- 不清除 BLE MAC、AuthKey、Label SN、产品型号和其他量产身份；
- 不清除 JL 音频参数、USB 配置、校准数据和其他模块拥有的 VM；
- 不直接把 `flash_get_sn_data()` 当成 RDX 量产身份接口；
- 量产固件不得保留完整协议身份与密钥日志；当前开发调试阶段允许开发人员采集完整 AppKey、AuthKey、Label SN 和线上报文，量产前必须统一关闭。

## 3. 当前基线与业务缺口

### 3.1 当前代码已经具备

| 能力 | 当前实现 | 说明 |
| --- | --- | --- |
| BLE 广播与扫描响应 | 已有 | Manufacturer Data 中已有产品字段、Bound 字节和 4 B Ability |
| GATT Identity | 已有 | 当前为 95 B Charge Case 兼容格式 |
| Battery | 已有 | 固定开发值 100% |
| Version | 已有 | 使用兼容配置中的硬件/固件版本 |
| AppKey | 已有 | 成功后进入 `APP-ready`，失败后返回失败并断开 |
| RTC | 部分兼容 | 只校验并回显时间戳，不设置或持久化系统 RTC |
| OS Type | 已有 | 只做兼容 ACK |
| PING/PONG | 已有 | 用于通路诊断 |

### 3.2 当前缺口和风险

| 项目 | 当前状态 | 本方案处理 |
| --- | --- | --- |
| Device Ability | 开发命令发现组合 `0x00000EA2` | 广播输出 `A2 0E 00 00`；仅用于打开 APP 页面和发现 Wire，不表示业务已实现 |
| Device Base Info | Identity 已覆盖 | 第一批不重复建立第二套基础信息结构 |
| `authsn` | 第一批已实现 | AppKey 后才允许返回；目标 APP Golden Trace 待完成 |
| `cofftime` | 第一批已实现 | 返回真实禁用值 0，线上单位为分钟；目标 APP Golden Trace 待完成 |
| `offtime` 设置 | 未实现 | 当前 Type-C 自动关机被强制关闭，本阶段不实现 |
| Bound 运行时状态 | 第二批已实现 | RDX 独立版本化状态存储，广播读取当前 RAM 状态 |
| APP 绑定 | 第二批已实现 | 只改变 RDX Bound 状态，不触碰 BLE Bonding、USB 或音频 |
| APP 解绑 | 第三批已实现 | 只清理 RDX 可变状态，成功 ACK 后延迟断开当前 RDX BLE |
| 恢复出厂 | 第三批已实现 | 只恢复 RDX 状态默认值，不清理其他模块和量产身份 |

### 3.3 当前兼容身份继续冻结

业务移植期间继续保持当前开发兼容身份：

```text
Local Name   = Zenchord Case 0000
Product Code = 603
Factory Code = ZENCHD
Product Type = E1
Self Mark    = NV
Role         = Charge Case compatibility
```

不得在同一批次同时切换正式 Type-C 产品身份。否则 APP 页面或连接行为变化时，无法判断是身份字段变化还是业务命令变化导致。

### 3.4 `rdx_mvp0_compat_config.h` 宏字典

`RDX_COMPAT_` 表示“当前 APP 兼容身份所使用的配置值”，不表示这些宏都是功能开关。该文件中的宏分为四类：

1. 产品能力选择：只有 `RDX_COMPAT_DEVICE_ABILITY`；
2. BLE 线上身份和协议布局：Local Name、Product/Factory Code、Product Type、Self Mark、协议版本；
3. 开发占位值：固定电量、AuthKey、Wi-Fi MAC、Label SN；
4. 认证和传输参数：AppKey 白名单、广播间隔、版本应答。

产品是否启用某项 RDX 业务，只看 `RDX_COMPAT_DEVICE_ABILITY`。其余宏不得被当成业务模块开关，也不得为启用某项能力而联动修改。

| 宏 | 当前值/形态 | 实际用途 | 配置边界 |
| --- | --- | --- | --- |
| `RDX_COMPAT_LOCAL_NAME` | `"Zenchord Case 0000"` | BLE Complete Local Name，并作为当前兼容设备名返回 | 线上身份字段；切换正式产品身份时统一修改，不控制任何业务 |
| `RDX_COMPAT_PRODUCT_CODE` | `"603"` | Manufacturer Data 起始的 3 B ASCII 产品代码，供 APP 扫描识别和产品路由 | 线上身份字段；必须与 APP 支持的产品档案一致 |
| `RDX_COMPAT_FACTORY_CODE` | `"ZENCHD"` | Manufacturer Data 中 BLE MAC 后的 6 B ASCII 厂商代码 | 线上身份字段；不是生产烧录厂代码，也不是功能开关 |
| `RDX_COMPAT_PRODUCT_TYPE` | `"E1"` | Manufacturer Data 中协议版本后的 2 B ASCII 产品/协议类型 | 参考工程未提供 `E1` 枚举说明，当前按不透明兼容字段原样保留 |
| `RDX_COMPAT_SELF_MARK` | `"NV"` | Manufacturer Data 最后的 2 B ASCII 自标识/兼容身份尾标，线上字节为 `4E 56` | 参考工程只称其为 Self Mark，未给出枚举或进一步业务定义；按不透明字段冻结。它不是颜色码，也与录音标记、`RDX_ABILITY_RECORD_MARK`、`*APP#recmark#` 无关 |
| `RDX_COMPAT_PRODUCT_IS_CHARGE_CASE` | `1` | 选择 GATT Identity 的 Charge Case 兼容数据布局；当前生成 `C,...` 的 95 B Identity | 身份报文布局选择，不宣告充电、存储或录音能力 |
| `RDX_COMPAT_DEVICE_ABILITY` | 具名 Ability 按位或 | 广播 32 bit Ability；同时由 `rdx_integration_config.h` 自动派生业务编译门控和源码裁剪 | 当前产品唯一的 RDX 能力选择入口；不得再增加 Pause、Mark 等平行产品开关 |
| `RDX_COMPAT_INCLUDE_PROTOCOL_VERSION` | `1` | 决定 Manufacturer Data 是否携带 1 B 协议版本 | 线上布局兼容开关；修改后 Product Type 和 Self Mark 的字节位置也会改变 |
| `RDX_COMPAT_PROTOCOL_VERSION` | `0x17` | `RDX_COMPAT_INCLUDE_PROTOCOL_VERSION=1` 时写入 Manufacturer Data 的单字节协议版本 | 这是线上原始字节，不是字符串 `"1.7"`；需按 APP Golden Trace 冻结 |
| `RDX_MVP0_FIXED_BATTERY_LEVEL` | `100` | GATT Battery Level 和 `*DEV#battery#...` 应答使用的固定开发电量 | MVP0/开发兼容值，不代表已接入真实电量采样 |
| `RDX_BLE_ADV_INTERVAL` | `160` | BLE 广播间隔，单位为 0.625 ms；当前为 100 ms | 传输参数，不是毫秒值，也不控制业务模块 |
| `RDX_COMPAT_FIRMWARE_VERSION` | `"1.0.0"` | `*DEV#version#<hardware>#<firmware>#` 的固件版本字段 | APP 展示/兼容字段；应由正式版本发布流程维护 |
| `RDX_COMPAT_HARDWARE_VERSION` | `"0.0.1"` | `*DEV#version#<hardware>#<firmware>#` 的硬件版本字段 | APP 展示/兼容字段；不是板级编译选择 |
| `RDX_COMPAT_APP_KEY_PRIMARY` / `_1` / `_2` / `_LIST` | 3 个 16 B ASCII 项 | AppKey 解密后允许通过认证的兼容白名单及其聚合列表 | APP 认证配置；不是设备的 AuthKey，也不控制 Device Ability |
| `RDX_COMPAT_AUTH_KEY` | 24 个 ASCII `0` | 当前 Identity 和 `authsn` 使用的逐设备授权码开发占位值 | 仅限开发；量产应由认证码 Provider/烧录数据提供，不能保留全零值 |
| `RDX_COMPAT_WIFI_MAC` | 12 个 ASCII `0` | 当前 `authsn` 使用的 Wi-Fi MAC 开发占位值 | 目标当前未接入 Wi-Fi 身份；不能解释为真实硬件 MAC |
| `RDX_COMPAT_LABEL_SN` | 16 个 ASCII `0` | 当前 Identity 和 `authsn` 使用的标签 SN 开发占位值 | 与录音文件 SN/文件名不是同一概念；量产应由认证码 Provider/烧录数据提供 |

Manufacturer Data 中相关字段的实际顺序为：

```text
PRODUCT_CODE(3 B ASCII)
+ reversed BLE MAC(6 B binary)
+ FACTORY_CODE(6 B ASCII)
+ mode/bound(1 B)
+ DEVICE_ABILITY(4 B little-endian)
+ [PROTOCOL_VERSION(1 B, optional)]
+ PRODUCT_TYPE(2 B ASCII)
+ SELF_MARK(2 B ASCII)
```

其中 `Self Mark` 这个命名来自参考工程。它是所有参考产品共用的固定尾标，不随产品颜色变化；参考配置又在 `FACTORY_CODE` 旁保留过 `NEVIEW` / `NvEasy` 注释，所以 `NV` 更像参考方案提供方的自标识缩写，但源码没有正式定义，不能将这个推测写成协议事实。现有代码和日志只能证明其位置、长度和值；在获得正式协议定义前，不对其强行扩写，也不据此增加业务逻辑。

参考工程在 `RDX_SELF_MARK` 下一行还定义了 `RDX_BLE_ADV_DEV_COLOR_POSITION (18)`，但全工程没有任何引用，广播组包也没有读取或写入颜色值。按当前含协议版本的 Manufacturer Data 从 0 开始计算：Ability 位于偏移 16～19，Self Mark 位于偏移 23～24；偏移 18 落在 Ability 内，并不指向 `NV`。因此该 Color Position 只能视为未接入当前报文的遗留宏，不能据此把 Self Mark 解释为颜色码。

## 4. 协议事实与术语边界

### 4.1 设备能力是 32 bit 位域

参考工程使用能力位按位或组合，而不是把能力值当成无语义整数：

```c
#define RDX_DEVICE_ABILITY \
    (ABILITY_CONFERENCE_RECORDING | ABILITY_RTC)
```

当前 `0x22` 即 `BIT(5) | BIT(1)`。Manufacturer Data 按低字节到高字节依次写入 4 B：

```text
Byte 0 = ability[7:0]
Byte 1 = ability[15:8]
Byte 2 = ability[23:16]
Byte 3 = ability[31:24]
```

公共 RDX 协议头应定义已知功能位，产品配置只负责选择并按位或：

| 位 | 公共含义 | 当前产品 |
| ---: | --- | --- |
| 7 | Local Storage | 开发命令发现启用；业务未实现 |
| 6 | Wi-Fi AP | 不启用 |
| 5 | Conference Recording | 开发命令发现启用；业务未实现 |
| 4 | Call Recording | 不启用 |
| 3 | Conference Noise Reduction | 不启用 |
| 2 | Classic Bluetooth | 不启用 |
| 1 | RTC | 开发命令发现启用；当前回显不等于完整 RTC 能力 |
| 0 | Multimedia Recording | 不启用 |
| 15 | Left/Right 1V1 | 不启用 |
| 14 | Wi-Fi AP V2 | 不启用 |
| 13 | Child/Parent | 不启用 |
| 12 | Network | 不启用 |
| 11 | Flashnote | 开发命令发现启用；业务未实现 |
| 10 | Record Mark | 开发命令发现启用；业务未实现 |
| 9 | Record Pause/Resume | 开发命令发现启用；业务未实现 |

保留位保持 0。定义或广播能力位不等于对应业务已编译或实现；当前六个置位只用于目标 APP 命令发现，协议层仍只处理本批已经实现的命令。

### 4.2 三种“绑定”必须分开

| 名称 | 命令 | 含义 | 本阶段 |
| --- | --- | --- | --- |
| APP 绑定状态 | `*APP#bound#...` | APP 与当前 RDX 设备的业务绑定标志 | 第二批 |
| APP 主动解绑 | `*APP#unbound#...` 或 Bound 命令的解绑分支 | 清除 RDX 业务绑定状态 | 第三批 |
| 充电仓与耳机配对 | `*APP#devpair#...` / `*APP#devunpair#...` | 仓与外部耳机的 Auth/MAC/SN 配对 | 不移植 |

APP Bound 状态不是 BLE Security Manager Bonding，也不是经典蓝牙配对数据库。实现 APP 绑定不得调用 `USER_CTRL_DEL_ALL_REMOTE_INFO`、TWS 清配对或 JL Unicast 绑定接口。

### 4.3 协议事实的优先级

当参考头文件、701 实现和 APP 实际行为不一致时，按以下优先级冻结合同：

1. 目标 APP 的 Golden Trace；
2. 已确认的正式 RDX 协议说明；
3. 701 参考工程的实际线上实现；
4. 参考头文件中的注释和变量名。

待机时间就是已知反例：参考头文件把字段注释为秒，但 701 的 `sys_get_auto_off_time()` 和 `sys_set_auto_off_time()` 实际按分钟读写。因此本工程线上单位明确采用分钟，并在 Golden Trace 中逐字节确认。

## 5. 目标模块划分

### 5.1 依赖关系

```text
rdx_mvp0_compat_config.h
        │
        ├──────────────► rdx_protocol_defs.h
        │                       │
        ▼                       │
rdx_identity ───────────────────┤
        │                       │
        │ runtime Bound         ▼
        └──────────────► rdx_device_state
                                ▲
                                │
rdx_mvp0_protocol ─────► rdx_device_management
        │
        ├──────────────► rdx_identity
        ├──────────────► rdx_platform_br56
        └──────────────► Transport send/disconnect callbacks
```

`rdx_mvp0_protocol` 只拥有会话状态、命令识别、认证门控、报文编码和发送时序。它不得直接调用 `syscfg_read()` / `syscfg_write()`，也不得直接修改 USB、音频或 JL 全局状态。

### 5.2 文件职责

| 文件 | 阶段 | 职责 |
| --- | --- | --- |
| `rdx_protocol_defs.h` | 第一批新增 | 公共命令常量、Ability 位定义和与产品无关的线上字段定义 |
| `rdx_mvp0_compat_config.h` | 第一批修改 | 当前产品静态兼容配置、暂存 Wi-Fi MAC、产品选择的 Ability 组合 |
| `rdx_identity.[ch]` | 第一批扩展 | 量产身份记录解析、BLE MAC、AuthKey、Label SN、Identity、Manufacturer Data；第二批读取运行时 Bound |
| `rdx_platform_br56.[ch]` | 第一批新增 | BR56 产品适配接口；认证码块读取和待机时间查询 |
| `rdx_mvp0_protocol.[ch]` | 各批扩展 | 命令解析、`app_ready` 门控、线上应答、ACK 后动作调度 |
| `rdx_device_state.[ch]` | 第二批已新增 | RDX 可变状态默认值、校验、VM 读写和版本化兼容占位 |
| `rdx_device_management.[ch]` | 第二批新增、第三批扩展 | 绑定、解绑、恢复默认值的业务边界和幂等状态转换，不包含线上字符串 |
| `rdx_ble_transport_br56.[ch]` | 第三批复用 | 现有 send/disconnect 已满足只断开当前 RDX BLE；断开后从最新状态重建广播，无需修改 Transport |
| `rdx_protocol_entry.[ch]` | 原则上不改职责 | 只负责 RDX 模块生命周期 |

不新增公共的 `rdx_app.c`，也不恢复 701 的大一统业务入口。

### 5.3 构建门控

新增源码继续由 `SDK/build/genFileList.c` 在 `#if TCFG_RDX_ENABLE` 下统一注入。不得给 `rdx_device_state`、`rdx_device_management` 或 `rdx_platform_br56` 增加绕过最终门控的独立构建入口。

`TCFG_RDX_ENABLE=0` 时必须满足：

- 不编译上述新增源码；
- 不分配 RDX VM 状态；
- 不注册业务命令、定时器或断连动作；
- 不改变非 RDX 的 BLE、USB 和 RAM 配置。

## 6. 第一批：只读设备业务

### 6.1 实施范围

第一批只允许：

1. 将 Ability 魔数改为公共具名位组合；
2. 使用具名位组合配置当前 Ability；第一批提交时为 `RDX_ABILITY_NONE`，后续开发命令发现阶段临时启用六个目标位；
3. 增加 `*APP#authsn#` 查询和应答；
4. 增加 `*APP#cofftime#` 查询和应答；
5. 增加只读 Provider/Adapter 接口；
6. 增加结构化开发调试日志，完整记录 APP 写入、设备上报和认证字段，量产前统一关闭敏感报文输出。

### 6.2 Ability 实现

公共头定义能力常量，产品配置使用：

```c

    (RDX_ABILITY_RTC                                   | \
     RDX_ABILITY_CONFERENCE_RECORDING                  | \
```

## 7. 第二批：APP 绑定与运行时 Bound

### 7.1 进入条件

第二批代码实施前核对了以下静态和协议边界；第一批仍有部分实机项目待补测，故本批只提交低副作用代码，不开放第三批动作：

- Ability 和其他扫描响应字段逐字节核对通过；
- MVP0 握手与 USB Speaker 共存无回归；
- 干净构建、Map 和 RDX OFF 检查通过。

### 7.2 RDX 状态结构

新增单一、版本化的状态结构：

```c
#define RDX_DEVICE_STATE_VERSION    1

typedef struct {
    u8 version;
    u8 bound;
    u8 reserved[2];
} rdx_device_state_t;
```

状态模块负责：

- 初始化默认值；
- 读取 VM；
- 校验读取长度、版本和 `bound` 合法性；
- 写入成功后更新 RAM；
- 提供只读快照；
- 恢复出厂时回到默认值；
- 屏蔽 `syscfg_read()` / `syscfg_write()` 细节。

当前产品默认值为未绑定。读取失败、长度不符、版本不匹配或 `bound > 1` 时，RAM 回退为默认未绑定并记录日志；不要在每次异常启动时立即反复写 VM，等首次合法状态变更时再落盘。

### 7.3 VM ID 规划

RDX 状态必须使用当前产品 `user_cfg_id.h` 中的用户自定义 VM ID，不复用 701 的 `VM_RDX_NOTTA_BOUND_STATUS=149`，因为当前 BR56 SDK 的 149 已被闹钟配置占用。

当前产品最终使用用户自定义区中的 ID 15：

```c
#define CFG_RDX_DEVICE_STATE    15
```

原建议 ID 14 未采用：它与未启用的公共模块配置区存在潜在占用，不能作为本产品长期 VM 合同。ID 15 已完成全仓数值核对，未发现当前启用配置冲突。不得使用 50～99 的 SDK VM 保留区，也不得直接复制 701 的 RDX VM 编号。

### 7.4 写入事务语义

```text
读取旧状态
    │
    ├─ 目标值与旧值相同 ──► 幂等成功，不写 VM
    │
    └─ 目标值不同
            │
            ├─ syscfg_write 失败 ──► RAM 不变，返回失败
            │
            └─ syscfg_write 成功 ──► 更新 RAM，返回成功
```

协议层只能在状态模块返回成功后发送成功 ACK。若状态已经成功落盘但 ACK 发送失败，不做第二次写入回滚；断开后 APP 通过重连和幂等命令恢复一致性。

### 7.5 运行时 Bound 广播位

Bound 是运行时业务状态，不属于产品兼容配置。设备首次出厂、VM 无有效记录和恢复出厂时固定为未绑定；用户绑定或清除绑定后，由 `rdx_device_state` 更新 RAM 并持久化到 VM。Manufacturer Data 的 Bound 位始终来自该运行时状态：

```text
bound == 0 -> mode/bound byte 的 BIT(6) 为 0
bound == 1 -> mode/bound byte 的 BIT(6) 为 1
```

RDX 初始化顺序调整为：

```text
rdx_device_state_init
    └── rdx_identity_init
            └── rdx_ble_transport_init
                    └── build advertising data
```

绑定发生在连接期间时无需立即强制断连。当前连接正常结束后，Transport 恢复广播时会重新调用 `rdx_identity_fill_manufacturer_data()`，自然带上最新 Bound 位。

### 7.6 APP 绑定行为

参考协议使用 `*APP#bound#...`。从参考工程线上实现确认，本批请求只有一个十进制 `cmd` 参数；当前只接受以下请求：

```text
*APP#bound#1#
```

成功响应为：

```text
*DEV#bound#0#1#
```

其中第一个字段是结果码（`0` 成功、`1` 失败），第二个字段是当前持久化 Bound 值。第二批只开放“设置为已绑定”的分支：

```text
未认证        -> 忽略并记录
参数非法      -> 忽略并记录，不改变状态
已经绑定      -> 幂等成功，不写 VM，不断开
尚未绑定      -> 先成功落盘，再返回成功 ACK
ACK 发送失败  -> 保留已落盘状态，等待 APP 重连确认
```

`*APP#bound#0#` 当前作为未开放的解绑分支处理：记录 `unbind_deferred`，返回失败响应 `*DEV#bound#1#<current_bound>#`，不改变状态。未认证请求、长度错误、缺少结尾 `#` 或非 `0/1` 参数均不回包、不改变状态。解绑统一留到第三批完成完整时序后开放。

## 8. 第三批：解绑与恢复出厂

### 8.1 进入条件

第二批必须先完成：

- 绑定、正常断连、广播 Bound=1；
- 冷启动后 Bound=1；
- 重复绑定不重复写 VM；
- USB Speaker 活跃期间绑定不影响播放和枚举。

### 8.2 当前产品允许清理的内容

| 数据 | 解绑 | 恢复出厂 | 说明 |
| --- | ---: | ---: | --- |
| RDX Bound | 清除 | 清除 | RDX 自有可变状态 |
| 未来 RDX 用户设置 | 按协议决定 | 清除 | 必须仍属于 RDX 状态结构 |
| 当前 `app_ready` | 会话结束时清除 | 会话结束时清除 | RAM 会话态 |
| BLE MAC | 保留 | 保留 | 量产身份 |
| AuthKey | 保留 | 保留 | 量产身份/密钥 |
| Label SN | 保留 | 保留 | 量产身份 |
| Product Code/Type | 保留 | 保留 | 产品身份 |
| USB/UAC/HID 配置 | 保留 | 保留 | 非 RDX 所有 |
| JL 音频/EQ/CVP 参数 | 保留 | 保留 | 非 RDX 所有 |
| TWS/经典蓝牙数据库 | 不操作 | 不操作 | 当前产品不拥有对应 RDX 业务 |
| 存储介质 | 不格式化 | 不格式化 | Local Storage Ability 未启用 |

### 8.3 解绑时序

```text
收到解绑命令
    │
    ├─ app_ready == 0 ──► 忽略并记录
    ├─ transition_pending == 1 ──► 拒绝新的状态修改
    └─ 参数合法
            │
            ├─ 已经未绑定 ──► 幂等成功，不重复写 VM
            └─ 当前已绑定
                    │
                    ├─ VM 写失败 ──► 失败 ACK，保持连接和原状态
                    └─ VM 写成功
                            │
                            ├─ 发送成功 ACK
                            ├─ 标记 transition_pending
                            ├─ 延迟约 100 ms
                            └─ 只断开 RDX BLE
                                    └─ 以 Bound=0 恢复广播
```

如果状态已经成功清除但 ACK 无法发送，仍应断开 RDX BLE并以未绑定状态恢复广播；APP 可重连后再次发送幂等解绑确认最终状态。

参考 `unbound` 命令中的 `user_para` 和 `format_en` 可以为兼容目的解析。即使当前开发命令发现广播临时置位 Local Storage，存储业务仍未实现，不得因 `format_en=1` 格式化任何存储；`user_para` 也不得触发清经典蓝牙、改名、改 Mic Gain 或其他 701 副作用。

### 8.4 恢复出厂时序

`*APP#default#` 只恢复 RDX 自有可变状态：

1. 必须已进入 `APP-ready`；
2. 检查没有其他状态转换正在等待；
3. 将 RDX 状态恢复为默认未绑定；
4. 状态落盘成功后发送成功 ACK；
5. ACK 成功入队后延迟约 100 ms；
6. 结束当前 RDX BLE 会话；
7. 以默认未绑定状态恢复 RDX 广播；
8. USB Audio 持续工作，不执行 `cpu_reset()`。

即使当前状态已经是默认值，恢复出厂也应成功 ACK，并结束当前 RDX 会话，使 APP 观察到一次完整的恢复流程。

### 8.5 延迟动作生命周期

协议状态增加：

```text
state_transition_pending
post_ack_action
post_ack_timer_id
```

约束：

- 同一时刻最多一个状态转换；
- 等待断开期间拒绝新的绑定、解绑和恢复出厂；
- 连接提前断开时取消定时器并清状态；
- `rdx_mvp0_protocol_exit()` 必须取消定时器；
- RDX 停止后回调不得再访问已释放的 BLE Handle；
- 不使用阻塞 `os_time_dly()` 等待 ACK。

## 9. 报文与错误处理合同

### 9.1 通用解析规则

- 固定查询命令必须长度完全相等；
- 带参数命令必须检查前缀、字段数量、字段范围和结尾 `#`；
- 不对非 NUL 终止的 ATT Payload 直接调用无界字符串函数；
- 所有输出缓冲必须静态定长或有明确上限；
- 超出单次 ATT 有效 Payload 时返回失败，不做隐式分片，除非后续协议明确要求；
- 未知命令保持忽略，不导入 701 的全量命令解析器。

### 9.2 失败语义

| 场景 | 行为 |
| --- | --- |
| 未认证的只读管理命令 | 忽略并记录，不返回敏感信息，不主动断开 |
| 未认证的状态修改命令 | 忽略并记录 |
| AppKey 校验失败 | 保持 MVP0 现有行为：失败 ACK 后断开 |
| 报文格式错误 | 按 Golden Trace 决定失败 ACK 或忽略；不得越界解析 |
| VM 读取异常 | 默认未绑定，记录原因 |
| VM 写入失败 | RAM 和广播状态不变，失败 ACK |
| ACK 发送失败 | 不伪造成功日志；已落盘状态不回滚，通过重连和幂等命令恢复 |
| 状态转换进行中 | 拒绝新的状态修改，不覆盖 pending action |
| RDX 提前停止 | 取消定时器和异步动作，不触发迟到断连 |

### 9.3 日志要求

开发调试日志统一使用 `[RDX][RX]`、`[RDX][TX]`、`[RDX][DROP]`、`[RDX][AUTH]` 和 `[RDX][SESSION]` 分类，记录：

- APP 写入的完整 ASCII Wire；
- AppKey 的完整 32 B Wire Payload、解密后的 16 B AppKey 明文及十六进制值；
- 设备上报的完整 ASCII Wire、长度和发送返回值；
- 是否因 `app_ready=0` 被拒绝；
- 状态旧值、目标值和 VM 返回值；
- pending action 创建、取消和执行；
- 广播中最终 Bound 与 Ability 数值；
- ACK 发送返回值。

这些完整字段日志只适用于开发人员调试采集。量产固件必须关闭 AppKey、AuthKey、Label SN、未来量产授权数据和完整身份报文输出；不得把当前开发调试策略直接带入量产版本。
