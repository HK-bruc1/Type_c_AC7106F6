# USB MIC 上行链路测试点说明

## 1. 文档目的

本文记录 USB MIC 无声问题中两个代码测试点的作用、使用方法和结果判定：

- `SDK/apps/common/device/usb/device/uac_stream.c` 中 `uac_mic_stream_read()` 的 1 kHz 正弦波注入测试。
- `SDK/audio/framework/plugs/source/adc_file.c` 中 `adc_mic_output_handler()` 的 ADC 原始采样峰值统计。

两个测试点分别从 USB 上行出口和 ADC 输入入口验证链路，可以把故障快速划分为 USB/手机侧、音频算法侧或 MIC 模拟前端。

术语说明：USB 扬声器数据由手机发送到耳机，属于 USB Audio 下行；USB MIC 数据由耳机发送到手机，属于 USB Audio 上行。本文所说的“ADC 后级链路”是从 ADC/CVP 之后到 USB MIC IN 端点及手机接收端的链路，也就是 USB MIC 上行链路，不是扬声器下行链路。

## 2. USB MIC 上行链路

本项目的 MIC 上行数据路径可简化为：

```text
两脚驻极体 MIC
    |
偏置电阻、耦合电容、PA2
    |
ADC 原始采样
    |  测试点 B：adc_file.c 峰值统计
CVP / SRC / 声道扩展
    |
PC MIC FIFO
    |
uac_mic_stream_read()
    |  测试点 A：uac_stream.c 1 kHz 注入
USB MIC IN 端点
    |
手机通话或电脑录音
```

测试点 A 绕过 MIC、ADC、CVP 和真实 PC MIC 数据，直接把固定正弦波写入 USB MIC 待发送缓冲区，用来证明 ADC 后方的 USB MIC 上行链路是否正常。测试点 B 不修改 ADC 数据，只统计 ADC DMA 原始样本，用来证明 PA2 是否真正采集到了数据。

## 3. 测试点 A：1 kHz USB MIC 注入

### 3.1 代码位置

文件：

```text
SDK/apps/common/device/usb/device/uac_stream.c
```

函数：

```c
int uac_mic_stream_read(u8 *buf, u32 len)
```

控制开关位于函数开头附近：

```c
#if 0 // 48K 1ksin
```

### 3.2 条件编译与正常数据路径

正常状态下，`uac_mic_stream_read()` 调用 `mic_tx_handler()`，从 PC MIC FIFO 读取 ADC/CVP 处理后的数据：

```c
if (mic_tx_handler) {
    return mic_tx_handler(mic_tx_handler_priv, buf, len);
}
```

`#if 0` 是测试音的条件编译门控。默认值为 `0` 时，正弦波代码完全不参与编译，执行 `#else` 中的正常 MIC 数据读取。临时改为 `#if 1` 后，编译器只保留测试音分支，函数不再调用 `mic_tx_handler()` 读取真实 MIC 数据。

### 3.3 注入原理与参数意义

USB 每次需要一个 MIC IN 数据包时都会调用：

```c
int uac_mic_stream_read(u8 *buf, u32 len)
```

主要参数和变量的意义如下：

| 参数或变量 | 意义 |
| --- | --- |
| `buf` | USB MIC IN 端点本次待发送的数据缓冲区。向这里写数据，相当于给手机提供本次 MIC PCM 数据包 |
| `len` | 本次 USB MIC 数据包需要的字节数。函数返回 `len` 表示已经准备好完整数据包 |
| `mic_samplerate` | 当前 USB MIC 采样率，用来选择 48 kHz 或 16 kHz 正弦表 |
| `mic_channel` | 当前 USB MIC 通道数；代码将同一个正弦样本复制到对应的 1、2、4 或 8 个通道 |
| `sin_48k` | 48 个 16 bit 样本，48 kHz 下正好构成 1 ms、一个周期的 1 kHz 正弦波 |
| `sin_16k` | 16 个 16 bit 样本，16 kHz 下正好构成 1 ms、一个周期的 1 kHz 正弦波 |
| `mic_tx_handler` | 正常模式下的真实 MIC 数据读取函数，数据来自 PC MIC FIFO |

启用测试分支后，程序根据 `mic_samplerate` 选择正弦表，根据 `mic_channel` 排列声道，然后把样本直接写入 `buf` 并返回 `len`。UAC 端点继续把这个缓冲区发送给手机，所以该过程不依赖 ADC 是否工作：

```text
固定1 kHz数组 -> buf -> USB MIC IN端点 -> 手机通话/录音
```

该测试绕过了以下环节：

- 驻极体 MIC 及其偏置、耦合电路。
- PA2 和 ADC。
- CVP、采样率转换及 PC MIC FIFO 中的真实音频数据。

因此，如果通话对端或录音能够听到测试音，可以证明：

- USB MIC IN 端点能够正常发送数据。
- 手机已经使用 USB 麦克风作为通话上行输入。
- UAC 描述符、端点发送及手机/电脑接收路径正常。

该结果只能证明 ADC 后级/USB MIC 上行链路正常，不能证明 MIC、PA2、ADC、CVP 或真实 PC MIC FIFO 数据正常。

### 3.4 操作与判定

临时启用：

```c
#if 1 // 48K 1ksin
```

编译、烧录后打开手机通话或电脑录音：

- 对端或录音中能听到连续的高音调：USB MIC 上行链路正常，故障在 ADC、CVP 或 MIC 模拟前端。
- 对端完全听不到测试音：继续检查 UAC 枚举、MIC IN 端点、手机通话路由和主机兼容性。

正弦波峰值约为 `16384`，约等于 16 bit 满幅的一半，听感会比较刺耳。测试时应降低接收端音量，避免长时间播放。

### 3.5 FIFO 堵塞与复位风险

当前测试分支会直接返回正弦波，不调用 `mic_tx_handler()`。与此同时，ADC/CVP 流程仍然向 PC MIC FIFO 写入数据，因此 FIFO 无人读取，可能出现：

```text
Cfifo readlock samples is too much, 1920, 1920
ASSERT: vmalloc_ 147
P33_EXCEPTION_SOFT_RST
```

现象通常表现为只听到一声短促、刺耳的“滴”声，随后芯片异常复位。该复位是测试方法的副作用，不代表 USB MIC 硬件掉电。

因此该测试只能短时使用。得到“能否听到测试音”的结论后，应立即恢复：

```c
#if 0 // 48K 1ksin
```

如果必须长时间输出测试音，应在覆盖 `buf` 前先调用一次正常处理函数以消费 FIFO 数据：

```c
if (mic_tx_handler) {
    mic_tx_handler(mic_tx_handler_priv, buf, len);
}
```

然后再向 `buf` 填入测试正弦波。该方式仍属于临时诊断代码，测试完成后也应恢复正常分支。

## 4. 测试点 B：ADC 原始采样峰值统计

### 4.1 代码位置

文件：

```text
SDK/audio/framework/plugs/source/adc_file.c
```

函数：

```c
static void adc_mic_output_handler(void *_hdl, s16 *data, int len)
```

ADC 原始采样日志使用独立的条件编译宏，定义在同一文件开头：

```c
#ifndef ADC_MIC_RAW_DATA_DEBUG_ENABLE
#define ADC_MIC_RAW_DATA_DEBUG_ENABLE     0
#endif
```

- `0`：默认关闭。统计字段、扫描代码和 UART 打印均不参与编译，没有运行时开销。
- `1`：启用原始 ADC 采样统计，每约 1 秒打印一次结果。

启用方法：

```c
#define ADC_MIC_RAW_DATA_DEBUG_ENABLE     1
```

诊断代码本身也由宏包围：

```c
#if ADC_MIC_RAW_DATA_DEBUG_ENABLE
if ((adc_hdl.bit_width == ADC_BIT_WIDTH_16) && hdl->ch_num && len) {
    /* 统计约 1 秒内的 min、max 和 peak */
}
#endif
```

### 4.2 原始采样测试原理

`data` 指向 ADC DMA 交付的原始 PCM 数据。峰值统计位于以下处理之前：

- `audio_common_mic_mute_en_get()` 软件静音。
- 音频流节点输出。
- CVP 降噪、动态处理及后续 USB MIC 传输。

因此该测试直接读取 ADC 已经采集到的数字样本，不会被 CVP 或 USB 层的处理结果干扰。如果 PA2 上存在声音信号并被 ADC 正常采集，`data[]` 中就会出现正负变化的非零 PCM 样本，统计结果不可能长时间保持 `min=0、max=0、peak=0`。

即使环境很安静，真实模拟 ADC 通常也会存在少量底噪；连续数十秒、每秒约 16000 个样本全部严格等于零，说明交给回调的 ADC 原始数据就是全零。由于统计位置早于 `audio_common_mic_mute_en_get()`，还能排除该软件静音逻辑造成的全零。

当前代码仅在 ADC 为 16 bit 时统计，符合本项目通话上行的 `16 kHz、单声道、16 bit` 配置。

### 4.3 函数参数与统计参数意义

回调函数参数：

| 参数 | 意义 |
| --- | --- |
| `_hdl` | 当前 ADC 节点句柄，可取得采样率 `sample_rate`、通道数 `ch_num` 和累计统计状态 |
| `data` | ADC DMA 本次交付的原始 PCM 数据地址；当前配置下每个元素是一个有符号 16 bit 样本 |
| `len` | MIC 单个通道本次采样数据的字节数，不是样本个数 |

统计代码中的参数：

| 参数 | 计算或意义 |
| --- | --- |
| `sample_num` | `(len * ch_num) / sizeof(s16)`，本次 DMA 数据块中需要检查的 16 bit 样本总数 |
| `debug_sample_count` | 每次增加 `len / sizeof(s16)`，累计单通道采样点数；达到 `sample_rate` 时约经过 1 秒 |
| `debug_sample_min` | 这一统计周期内出现的最小有符号样本，用于观察负半波和负向饱和 |
| `debug_sample_max` | 这一统计周期内出现的最大有符号样本，用于观察正半波和正向饱和 |
| `peak` | `max(abs(min), abs(max))`，表示该周期内最大的绝对幅度，便于快速判断有没有声音及是否削顶 |

这里打印的是 `peak`、`min` 和 `max`，不是只打印某一个瞬时采样点。瞬时样本可能刚好为零，不能代表整段数据；统计约 1 秒内的极值后，如果仍然三个参数全零，才足以说明这一秒收到的所有 ADC 样本均为零。

### 4.4 日志格式

代码约每秒打印一次：

```text
[ADC_MIC] peak:1234 min:-900 max:1234
```

字段含义：

- `peak`：最适合现场快速观察。说话或轻敲 MIC 时应明显增大；接近 `32767` 表示可能削顶。
- `min`：用于确认负向样本是否存在。正常交流音频通常应出现负值；接近 `-32768` 表示负向饱和。
- `max`：用于确认正向样本是否存在。正常交流音频通常应出现正值；接近 `32767` 表示正向饱和。

限频统计避免逐采样 `printf` 淹没 UART，降低打印对实时音频任务的影响。

### 4.5 结果判定

测试时应进入通话或录音状态，并连续说话、吹气或轻敲 MIC：

| ADC 日志表现 | 判断 | 下一步 |
| --- | --- | --- |
| 长时间 `peak:0 min:0 max:0` | ADC 原始数据全零 | 检查 MIC 偏置、极性、耦合电容、PA2 接线及 ADC 输入选择 |
| 静音时较小，说话时升到数百或数千 | MIC 和 ADC 已采到声音 | 检查 CVP、PC MIC FIFO及后级数据格式 |
| 长时间接近 `32767` 或 `-32768` | ADC 输入削顶或异常饱和 | 检查偏置电压、短路、输入增益和接地 |
| 只在启动第一秒出现单边大值，随后全零 | 耦合电容或 ADC 启动瞬态 | 忽略首秒，按后续持续数据判断 |

`peak` 的绝对门槛会受 MIC 灵敏度和 ADC 增益影响，判断时应优先观察“说话前后是否明显变化”，不要只依赖一个固定数值。

### 4.6 测试边界

ADC 峰值测试只能证明数字采样是否变化，不能直接证明 MIC 偏置电压正确。ADC 全零时仍需在通话过程中测量：

- PA0/MICLDO 对 AVSS 应约为 3.0 V。
- MIC 正极节点应有非零且低于 PA0 的直流偏置，常见约为 1～2.5 V。
- MIC 正极到 PA2 之间的耦合电容应连接可靠。
- 两脚驻极体 MIC 的负极/外壳应接 AVSS，正极接偏置节点。

## 5. 两个测试点的组合判定

| 1 kHz 测试音 | ADC 峰值 | 故障范围 |
| --- | --- | --- |
| 能听到 | 随声音明显变化 | USB 和 ADC 均正常，重点检查 CVP/格式转换/PC MIC FIFO |
| 能听到 | 持续全零 | USB 正常，故障位于 ADC 输入、MIC 偏置或硬件接线 |
| 听不到 | 随声音明显变化 | ADC 正常，故障位于 UAC、USB 端点或手机路由 |
| 听不到 | 持续全零 | 上下游均需检查，先确认 USB 测试音代码确实生效，再检查模拟前端 |

推荐测试顺序：

1. 短时启用 1 kHz 测试音，确认 USB 通话上行。
2. 立即恢复 `#if 0`，避免 PC MIC FIFO 堵塞和异常复位。
3. 将 `ADC_MIC_RAW_DATA_DEBUG_ENABLE` 改为 `1`，启用 ADC 限频峰值日志，确认 PA2 原始数据是否随声音变化。
4. ADC 全零时转向硬件测量；ADC 正常时转向 CVP 和 PC MIC 后级排查。

## 6. 本次问题的实测结论

本项目调试过程中得到以下结果：

- 启用 1 kHz 测试音后，通话端能够听到一声刺耳的测试音，随后因 PC MIC FIFO 未被消费而触发 `vmalloc_` 断言和异常软复位。这证明 USB MIC 上行及手机通话路由有效。
- 恢复正常 MIC 数据读取后，ADC 日志除启动瞬态外，连续约 25 秒为 `peak:0 min:0 max:0`。

据此可将故障定位在 PA2 之前的 MIC 模拟前端，优先检查：

```text
PA0/MICLDO -> R3 1.5 kΩ -> MIC 正极 -> 约 1 µF 耦合电容 -> PA2
```

测试完成后应将 `ADC_MIC_RAW_DATA_DEBUG_ENABLE` 恢复为 `0`。条件编译会同时移除统计字段、样本扫描和 UART 打印，避免量产固件保留诊断开销。
